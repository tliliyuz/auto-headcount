# ADR-004：自有登录替代企业 OIDC

- 状态：accepted
- 日期：2026-08-12
- 决策人：项目负责人（确认当前无外部企业身份提供方，改用自有登录）
- 替代：`ADR-003` §1「管理端登录与会话」的身份提供方部分；`ADR-003` 的区域、数据存储与保留基线不变

## 背景

`ADR-003` §1 原决策采用供应商无关的 OpenID Connect（OIDC）登录，优先接入业务方现有企业身份提供方，MVP 内不保存员工密码。该方案把账号生命周期和口令安全外包给外部 IdP。

2026-08-12 项目负责人确认：当前没有对接其他公司的企业身份提供方，登录由本系统自建，因此命中 `ADR-003` 的重新评估触发条件「业务方没有企业 OIDC 身份提供方」。

## 决策

管理端采用**自有账号口令登录**，替代企业 OIDC：

- `users` 保存账号与口令哈希（建议 argon2id 或 bcrypt，成本参数按硬件调整），不保存明文口令；日志、错误上报和审计元数据不得包含口令或口令哈希。
- 移除 `user_identities` 的 OIDC 外部身份映射语义；不再依赖任何外部身份提供方。
- 保留 `ADR-003` 的全部既有安全控制：不开放自主注册、仅管理员邀请/启用的用户可登录、本地 `users` + `role_assignments` 判定业务权限、服务端可撤销会话、`HttpOnly`/`Secure`/`SameSite=Lax` Cookie、管理端写操作 CSRF 防护、会话空闲 30 分钟失效且最长 12 小时、禁用用户与角色变更后现有会话可撤销。
- 新增自有口令控制：口令最小长度与复杂度要求、拒绝常见弱口令、登录失败限流与临时锁定、口令可轮换并支持强制首次改密、生产管理员账号启用多因素认证（如 TOTP）。
- 开发环境仅允许在 `development` 构建启用的 Fixture 登录与脱敏种子用户；测试与生产启动时必须拒绝该路径。

## 备选方案

- 沿用企业 OIDC（`ADR-003` 原方案）：需要外部企业身份提供方，当前不具备，保留为组织接入企业 IdP 后的迁移路径。
- 仅使用部署平台身份头：不能独立证明成员关系与业务角色，只能作为自有账号体系的补充输入，不单独承担授权。

## 后果

- 需要实现自有口令认证、口令哈希、登录限流与锁定、生产 MFA、会话撤销、RBAC 权限测试与审计中间件。
- 本系统承担完整账号生命周期：邀请、启用/禁用、口令重置、离职停用与删除。
- 测试/生产构建无法启用 Fixture 登录的门禁保持不变。

## 重新评估触发条件

- 组织接入企业身份提供方，希望改为 SSO/OIDC 登录。
- 需要客户自助门户或外部组织授权的复杂身份场景。
- 出现更强的口令合规或审计要求。
