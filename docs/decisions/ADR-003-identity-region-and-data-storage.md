# ADR-003：身份、部署区域与数据存储基线

- 状态：accepted（§1 身份提供方部分已部分被替代）
- 日期：2026-08-11
- 决策人：项目负责人（确认方案并批准进入后续开发）

> 2026-08-12 更新：§1「管理端登录与会话」的身份提供方决策已由 [ADR-004](ADR-004-self-managed-login.md) 替代为**自有账号口令登录**。本节其余安全控制（会话、Cookie、CSRF、MFA、Fixture 门禁）继续有效；区域与数据存储基线不受影响。

## 背景

系统将处理招聘职位、候选人画像、联系方式、原始简历片段和触达记录。现有规范要求登录、最小权限、字段加密和审计，但尚未确定认证方式、权限矩阵、测试/生产区域、原始响应保存格式及明确的数据保留基线。

本 ADR 是可实施方案，不替代业务方、数据提供方和法务对数据授权、保存期限及跨境处理的书面确认。在这些门禁完成前，测试和生产不得导入真实候选人数据。

## 决策

### 1. 管理端登录与会话

- 管理端采用供应商无关的 OpenID Connect（OIDC）登录，优先接入业务方现有企业身份提供方；系统不在 MVP 内保存或校验员工密码。
- 不开放自主注册。只有受邀且位于允许名单中的用户才能建立本系统账号。
- OIDC 只证明身份，系统仍以本地 `users` 与 `role_assignments` 判断业务权限；身份提供方的组映射只能作为授予角色的输入，不能绕过本地禁用状态。
- 登录完成后建立服务端会话，浏览器只保存 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie；管理端写操作执行 CSRF 防护，会话空闲 30 分钟失效、最长 12 小时。
- 生产管理员账号要求身份提供方启用多因素认证。用户禁用、角色变更和退出登录后，现有会话必须可撤销。
- 本地开发允许使用仅在 `development` 环境编译启用的 Fixture 身份适配器和脱敏种子用户；测试与生产启动时必须拒绝该适配器。
- 候选人不创建管理端账号，只通过高熵、可过期、可撤销且数据库仅保存哈希的落地页令牌访问白名单 DTO。

### 2. MVP 角色

| 角色 | 允许 | 明确禁止 |
|---|---|---|
| `operations` | 查看/同步职位，创建匹配任务，准备活动草稿，查看聚合漏斗 | 管理用户与连接密钥、导出联系方式、批准自己的批量触达 |
| `recruiter` | 查看获授权候选人，审核匹配，处理跟进，登记推荐结果 | 管理数据源、批量导出、修改系统权限 |
| `admin` | 管理用户角色、数据源元数据、系统开关、审计与保留任务 | 读取 Secret 明文；绕过触达审批与退订门禁 |

- 数据导出、批量触达批准、正式推荐、用户/角色变更和数据删除属于高风险权限，独立授权并强制审计。
- MVP 允许一名用户拥有多个角色，但触达活动的创建人与批准人不得是同一人；若团队规模暂时无法满足，真实批量触达保持关闭。

### 3. 环境与部署区域

- `development`：开发者本机 Docker Compose，只允许脱敏 Fixture 或经书面批准的最小测试样本；不得复制生产数据库。
- `test`：独立云账号/项目、网络、数据库、对象存储与 Secret，部署在中国大陆区域；默认只使用脱敏数据。受控 MCP 联调使用独立测试凭证。
- `production`：部署在中国大陆区域，使用容器运行时和同区域托管 PostgreSQL；数据库备份与灾备副本默认不得离开中国大陆。
- 测试与生产禁止共享数据库、密钥、消息渠道、域名 Cookie 或对象存储桶。
- 默认禁止把候选人个人信息发送到境外服务。启用境外 LLM、日志、监控、邮件、分析或客服服务前，必须完成数据流清单、最小化评估、合同与适用的数据出境合规流程，并另立 ADR。
- 具体云厂商和中国大陆城市区域待域名备案、短信资质、MCP 网络连通性、成本及业务连续性要求确认后选择；本 ADR 不绑定供应商。

### 4. PostgreSQL 中的数据分层

#### 原始 MCP 响应

- `raw_records` 采用追加写，不允许业务代码原地修改载荷。
- 可检索元数据以普通列保存：来源、同步批次、实体类型、外部 ID、Schema 版本、采集时间、载荷哈希、加密密钥版本和处理状态。
- 原始载荷经应用层信封加密后保存为 `bytea`；建议算法为 AES-256-GCM，数据密钥由部署平台密钥服务包装，主密钥不进入数据库、镜像或日志。
- 载荷解密只允许数据同步故障处理和受控重放，不向页面、普通查询接口或日志返回。
- 同一来源、外部 ID、内容哈希和同步批次建立去重约束；重放产生新的处理记录，不覆盖原始证据。

#### 规范化业务数据

- `jobs`、`candidates`、`matches` 等使用关系表、外键、唯一约束和迁移管理。
- 规范化记录保留 `source_connection_id`、`external_id`、`source_updated_at`、`raw_record_id` 和映射版本，以便追溯。
- 手机号、邮箱等联系方式单独存表并应用层加密；搜索与去重使用带独立密钥的 HMAC，不保存可逆的标准化明文索引。
- 落地页只能读取专用白名单投影，不得序列化业务表或解密原始载荷。

#### 审计日志

- `audit_logs` 追加写，应用角色无更新和删除权限；清理只能由独立保留任务执行。
- 至少记录：时间、操作者/系统主体、动作、资源类型与 ID、结果、请求关联 ID、来源 IP 的最小必要表示、权限判定和变更字段名。
- 审计元数据使用白名单，不保存简历正文、联系方式、令牌、Secret、会话 Cookie 或完整 MCP 请求/响应。
- 登录、角色变化、数据查看/导出、解密、同步、触达审批/发送、推荐、删除、系统开关和密钥轮换均必须审计。

### 5. 保留与备份工程基线

以下期限是工程默认上限，不代表已取得数据处理授权；上线前必须由业务方、数据提供方和法务书面确认，并允许按数据源配置更短期限：

| 数据 | 默认上限 |
|---|---|
| 原始 MCP 成功响应 | 规范化成功后 30 天 |
| 失败/异常原始响应 | 问题关闭后 30 天，最长 90 天 |
| 已关闭职位及其非敏感业务记录 | 关闭后 180 天 |
| 候选人画像与联系方式 | 最后一次获授权业务使用后 180 天；撤回授权或合法删除请求触发提前删除 |
| 审计日志 | 365 天；只保留最小必要证明 |
| 加密备份 | 35 天滚动保留，并覆盖到删除流程 |

- 退订后立即停止触达；为执行退订仅保留不可逆/HMAC 抑制标识和最小证明，不保留可用于继续营销的完整画像。
- 生产 PostgreSQL 开启加密备份和时间点恢复，目标暂定为 RPO 不超过 15 分钟、RTO 不超过 4 小时；每季度至少验证一次恢复。
- 所有期限必须通过定时保留任务执行并产生审计事件，不能依赖人工清表。

## 备选方案

### 自建邮箱密码认证

可降低对企业身份提供方依赖，但会新增密码存储、找回、多因素认证和账号生命周期风险，原不适合当前单人 MVP；2026-08-12 因无外部企业身份提供方，已由 [ADR-004](ADR-004-self-managed-login.md) 采纳为当前方案。

### 仅使用部署平台身份头

接入速度快，但身份头不一定证明企业成员关系，也不能代替本地业务角色和账号禁用，因此只能作为 OIDC 适配器输入，不能单独承担授权。

### 测试或生产部署在境外区域

可能获得更多云服务选择，但招聘个人信息的跨境数据流、供应商处理链和合规门槛尚未确认。当前默认境内处理以减少不必要的数据出境；确有需求时另立 ADR。

### 原始载荷只存对象存储

适合超大对象和低成本归档，但 MVP 数据量小，会新增存储权限、生命周期和一致性边界。首期存入 PostgreSQL 加密列；单条载荷或总量超过数据库阈值时再评估加密对象存储。

## 后果

- 需要实现自有账号口令认证（见 `ADR-004`）、本地 RBAC、会话撤销、权限测试和审计中间件。
- 真实数据联调前必须拿到数据授权、保留期限和区域确认；登录采用自有账号，不依赖外部身份提供方。
- 原始数据加密会增加密钥轮换、受控重放和恢复测试工作。
- 默认境内区域会限制部分境外 SaaS 的直接使用，但降低未评估跨境传输风险。

## 重新评估触发条件

- 业务方没有企业 OIDC 身份提供方。
- 需要企业客户自助登录或复杂组织权限。
- 生产用户或候选人数据来源不在中国大陆。
- 必须使用境外 LLM、日志、分析、邮件或灾备服务。
- 数据提供方给出不同的保存、删除或本地化要求。
- 原始载荷规模不再适合 PostgreSQL。
