# ADR-005：授权网页采集与本地可复算匹配

- 状态：accepted
- 日期：2026-08-13
- 决策人：项目负责人（确认供应方已开通 Web 平台账号；MCP 权限不足时允许在授权页面范围内采集）
- 替代：`docs/04-mcp-integration.md` 中“MCP 是唯一主数据接入方式”和“MVP 匹配只采用供应方评分”的既有口径

## 背景

真实联调确认：`wb.jobs.under_served` 能提供沉睡属性，`wb.jobs.get` 能补全 JD，但当前账号通过 `wb.jobs.list`/`wb.jobs.match_candidates` 可操作的职位与沉睡职位交集仅约 2 个。供应方 Web 平台账号在授权页面中可查看更完整的职位、候选人和简历信息。若继续把 MCP 当作唯一来源，数据权限会长期阻塞宽口径沉睡职位激活和本地闭环验证。

现有 CSDN-Agent 浏览器插件已经提供 Chrome/Edge 登录态复用、`userId + deviceId + browserSessionId` 路由、本地/远程 Relay、同源带 Cookie 请求、DOM/CDP 操作和设备绑定自动化。重新实现一套持有供应方 Cookie 的服务器爬虫会扩大凭证边界，也会重复建设浏览器执行能力。

网页采集会引入完整简历、联系方式和可识别候选人信息，且自建评分会改变匹配数据所有权与可复算口径，因此需要单独固化信任边界、数据分层和退出门禁。

## 决策

### 1. 数据源与职责

- 供应方 Web 平台成为正式授权数据源；MCP 保留为并列适配器，用于沉睡属性、低成本详情补全、供应方匹配结果对照和降级。
- CSDN-Agent 复用为**浏览器执行端**：登录态、Cookie、验证码和浏览器 Profile 留在员工本机，不进入 auto-headcount、Agent 上下文、任务载荷或日志。
- auto-headcount 继续拥有任务幂等、加密入库、规范化、脱敏、评分、审核、触达和漏斗状态；业务模块不依赖页面 DOM、选择器或供应方原始字段。
- 开发和 CI 不实时依赖供应方网站。真实页面仅用于受控集成验证；常规测试使用保留 Schema 与边界行为的完全虚构 Fixture/Golden Dataset。

### 2. 受限提取契约

CSDN-Agent 新增版本化、预审核的受限提取能力（拟定工具名 `csdn_run_extraction_contract`），而不是由生产任务传入任意 JavaScript、选择器或 URL。每个契约固定：

- 允许域名、只读 URL/请求方法和页面类型；
- 必填/可选字段、字段白名单和页面结构指纹；
- 最大页数、批量、速率、超时和停止条件；
- PII 分类、浏览器内最小化规则和契约版本；
- `AUTH_REFRESH_REQUIRED`、`PAGE_CONTRACT_CHANGED`、`SOURCE_PERMISSION_BOUNDARY`、`BROWSER_OFFLINE` 等失败语义。

插件通用 MCP 工具只用于探索页面和制定契约，不作为长期批量采集接口。页面结构不符合契约时失败关闭，不猜测字段、不继续写库。

### 3. 敏感数据传输与存储

- 职位字段和已经最小化的候选人特征可以通过受限 Relay 回执传输。
- 完整简历与联系方式不得作为通用 MCP 工具结果或 Agent 对话内容返回。浏览器执行端使用短期、单任务、单次消费的 ingestion ticket，直接通过 HTTPS 提交到 auto-headcount 采集入口；Relay/Agent 只接收数量、内容哈希、游标和机器错误码。
- 采集入口先校验来源、任务、契约版本、大小和 Schema，再把必要原始载荷应用层加密保存；原始正文不得进入普通日志或审计元数据。
- 联系方式进入独立加密存储并使用 HMAC 去重/抑制；匹配模块无权读取手机号、邮箱、微信号或原始页面令牌。
- 匹配输入使用独立脱敏评分投影，只保留技能、年限、行业、职级、城市、教育层级、证书、薪资期望和活跃度等必要特征。

### 4. 本地匹配

- 本地建立确定性、版本化、可复算的硬过滤与加权评分；供应方 `match_candidates` 分数降为外部对照字段，不再决定业务主流程。
- 每个结果保存规范化输入版本/哈希、规则版本、维度分、总分、证据、缺失项、风险、生成时间及数据来源。
- 首版不引入向量检索、模型微调或黑盒自动决策。若使用 LLM 提取特征，默认只发送脱敏文本；向境外模型发送候选人个人信息仍受 `ADR-003` 门禁。

### 5. 运行与停止边界

- 采集任务绑定明确的 `userId + deviceId`；浏览器离线或登录失效进入等待/人工刷新状态，不静默切换账号或设备。
- 默认并发 1，按数据源配置小时/日预算；验证码、429、异常跳转、连续契约失败或全局开关关闭时立即停止。
- 不绕过验证码、访问控制、平台风控或账号授权范围，不使用代理池扩大采集范围。
- 正式批量采集前保存可追溯的授权范围：允许页面/字段、自动化频率、用途、保存期限和删除要求。当前负责人确认允许以已开通 Web 账号做受控采集；供应方条款或更严格书面要求到达后以更严格者为准。

## 备选方案

- 继续只用 MCP：实现简单且上游自带部分脱敏，但可操作沉睡职位交集过小，无法支撑宽口径闭环。
- 新建服务器 Playwright 采集器：适合无人值守，但需要把平台凭证和登录态迁出用户浏览器，扩大信任边界；当前不选择。
- 让 Agent 使用通用浏览器工具逐页读取：适合探索，但输出不稳定，完整简历可能进入模型上下文和日志，不满足生产采集要求。
- 完全采用供应方评分：启动快，但费用、权限和评分状态由供应方控制，无法保证本地闭环和跨供应方复用。

## 后果

- 需要同时修改 CSDN-Agent 与 auto-headcount：前者增加受限提取契约和直传通道，后者增加浏览器数据源、ingestion ticket、采集入口、候选人/联系方式分层和本地评分。
- 浏览器在线、设备绑定和人工刷新登录态成为运行条件；它不是纯服务器无人值守采集器。
- 必须维护页面契约 Fixture、脱敏回归测试、限速/熔断、字段级来源追溯和数据删除能力。
- MCP 现有链路继续可用；Web 适配器可按开关独立停用，回滚不会破坏 MCP 数据。
- 本 ADR 只确认规范（`specified`）；未实现和验证受限提取工具、采集入口或本地评分前，不得声明功能可用。

## 重新评估触发条件

- 供应方提供覆盖职位、候选人和简历的正式 API，或禁止自动化采集。
- 需要无人值守运行且无法保持员工浏览器在线。
- 采集范围扩大到新的账号、组织、域名或敏感字段。
- 使用外部 LLM 处理未脱敏简历，或改变候选人联系方式的授权、保留和删除规则。
- CSDN-Agent Relay 变为多租户/多服务器部署，现有设备与路由边界发生变化。
