# 安全与合规基线

本文是工程基线，不替代法务意见。数据使用范围、触达依据和保留期限需由业务方与数据提供方书面确认。

## 1. 立即事项

- 轮换已经通过聊天明文发送的 MCP Secret。
- 职位与候选人画像数据落库已由项目负责人确认（2026-08-12；2026-08-14 范围更新为：含真实姓名的候选人画像按敏感业务 RBAC + 应用层加密 + 审计落库），暂不设固定保留期限上限；触达授权仍待 M4 前确认。
- 使用脱敏样本开发，禁止把真实简历加入仓库或测试夹具。
- 保存负责人对 Web 采集的可追溯授权范围；在正式批量采集完整简历/联系方式前，固化允许页面、字段、频率、用途、保存期限和删除要求。
- 在短信/邮件网关接入前确认模板、签名、退订和频控要求。

## 2. 数据分类

| 等级 | 示例 | 控制措施 |
|---|---|---|
| 公开/内部 | 脱敏职位摘要、规则版本 | 登录控制或按页面用途公开 |
| 敏感业务 | 完整 JD、候选人画像、脱敏简历详情、LLM 评分证据/风险 | 角色授权、应用层加密、审计、导出限制 |
| 高敏感 | 手机号、邮箱、原始简历、访问令牌 | 字段加密、严格授权、最短保留 |
| 密钥 | MCP/LLM/SMS Secret、浏览器 Cookie/Authorization/验证码 | Secret Manager 或浏览器本地边界、不可入库/日志/Agent 上下文 |

## 3. 产品控制

- 候选人页面仅显示经过字段白名单处理的职位内容：公司名称隐藏、薪资只显示范围、地点只显示城市。
- 链接使用高熵随机令牌，数据库只存令牌哈希，并支持过期和撤销。
- 触达前检查退订、黑名单、发送频率和人工审批状态。
- 每封邮件和合适的短信场景提供明确的拒绝联系途径。
- 不使用暗示性默认选项，不把浏览页面等同于同意被联系。
- 推荐前由人工确认候选人身份、意向和职位匹配。

## 4. 工程控制

- HTTPS、数据库传输加密和高敏字段应用层加密。
- 管理端采用强认证、最小权限和会话过期。
- 生产数据库禁止开发人员日常直连；访问需审计。
- 日志过滤请求头、手机号、邮箱、简历正文和页面令牌。
- CSDN-Agent 交互式浏览器采集按 `userId + deviceId + browserSessionId` 绑定；持久化批量任务只保存 `userId + deviceId`，由 Relay 在该作用域内选择当前活跃页，禁止持久化或猜测 Session。Cookie、口令、验证码和原始 Authorization 始终留在浏览器，禁止通过任务载荷、Relay 结果或 Agent 对话传输。
- 生产采集只运行预审核的只读提取契约；禁止由业务任务下发任意脚本、选择器、域名或写请求。默认单并发并设置小时/日预算、熔断和全局停止开关。
- 完整简历与联系方式使用短期、单任务、单次消费的 ingestion ticket 直接提交受控入口；Relay/Agent 仅接收计数、哈希、游标和机器错误码。
- 匹配引擎只读取通过版本化 Schema 和残留 PII 扫描的脱敏评分投影，无权读取联系方式保险箱或原始简历；真实样本生成测试数据时必须重新虚构化，而非仅打码。
- LLM 调用前必须验证候选人投影 `residual_pii_scan=passed`，请求不含本地/供应商实体 ID、原始 URL、姓名、联系方式或受保护个人属性。残留 PII 检测、输入超限或输出 Schema 校验失败时关闭，不调用未审批模型降级。
- LLM 运行记录只在业务表保存模型/Prompt/Schema 版本、哈希、机器错误码和经验证的结构化投影；脱敏简历详情和 LLM 原始响应仍应用层加密，不进普通日志或审计元数据。
- 依赖与镜像定期扫描，生产密钥按环境隔离。
- 备份加密并定期验证恢复；删除流程覆盖备份生命周期。

### 4.1 身份与权限基线

- 管理端使用自有账号口令登录（`ADR-004`），不开放自主注册，只保存口令哈希（argon2id/bcrypt），不保存明文口令。
- 登录成功只建立主体身份；业务权限由本地启用用户、角色和权限策略决定。
- 口令或 TOTP 校验失败均计入连续失败锁定（阈值 5 次、锁定 15 分钟），锁定期满自动恢复；统一失败文案防账号枚举。
- MVP 角色为 `operations`、`recruiter` 和 `admin`，高风险操作使用独立权限并强制审计。
- 生产管理员要求多因素认证：TOTP 共享密钥由初始化脚本生成并预置（输出 otpauth 配置 URI），登录必须通过口令 + 动态码；会话使用服务端可撤销记录和安全 Cookie。
- 开发 Fixture 登录不得在测试或生产环境启用。

### 4.2 区域与跨境基线

- 2026-08-12 项目负责人确认：测试/生产区域为中国大陆，不绑定具体云厂商。
- 开发只使用脱敏 Fixture；测试和生产默认部署在相互隔离的中国大陆区域。
- 生产数据库、备份和灾备副本默认留在中国大陆。
- 向境外 LLM、日志、监控、邮件、分析或其他 SaaS 发送候选人个人信息默认禁止；启用前必须完成数据流、必要性、合同和适用的数据出境合规评估。
- 具体云厂商和区域城市由网络连通、备案、资质、成本和业务连续性要求共同确定。

选择中国大陆区域是当前减少不必要跨境数据流的保守架构决策，不表示所有招聘系统均被法律无条件要求境内存储。是否构成数据出境、适用何种程序和能否使用境外处理者，必须结合主体性质、数据类型、数量、必要性和实际传输链路判断。

### 4.3 加密、审计与保留基线

- 原始 MCP/Web 必要载荷和候选人联系方式采用应用层信封加密，密钥由部署环境的密钥服务管理并支持版本轮换；联系方式独立存储并使用 HMAC 去重/抑制。
- 审计日志追加写，记录身份、权限判定、数据访问/导出、同步、触达、推荐、删除和系统开关，但不得保存敏感正文。
- 数据保存遵守实现处理目的所必要的最短时间；工程默认上限和删除触发器见 `ADR-003`。项目负责人已确认脱敏候选人数据可入库且暂不设固定保留期限上限（2026-08-12），收到数据提供方更短期限或删除要求时以更严格者为准。
- 以上三节由 `ADR-003` 固化，但不得据此宣称已取得真实数据处理授权或已完成上线合规审查。

## 5. 上线门禁

以下任一项未完成，不得对真实候选人批量触达：

- 数据来源与使用权限未确认。
- Web 自动化采集范围、字段、用途、频率、保存和删除要求未形成可追溯记录，或供应方条款明确禁止该行为。
- 退订、黑名单或频控不可用。
- 页面仍暴露企业、联系方式或候选人敏感信息。
- 触达活动没有审批人和审计记录。
- 密钥仍使用已暴露值或出现在客户端/日志中。
- 无法停止正在运行的活动或撤销落地页链接。
- 身份、区域、数据保留与跨境处理方案尚未被接受并取得业务/数据提供方书面确认。

以下任一项未完成，不得对真实网页进行无人值守或批量候选人/简历采集：

- 受限提取契约、域名白名单、限速、熔断和停止开关未验证。
- Cookie/Authorization、完整简历或联系方式能够出现在 Agent/MCP 结果、任务表、普通日志或审计元数据中。
- ingestion ticket 不能过期、单次消费、绑定任务/契约或限制载荷大小。
- 浏览器离线、登录失效、验证码、429 或页面契约变化时仍继续写入业务数据。

以下任一项未完成，不得对真实候选人执行 LLM 详情评分：

- LLM 供应商/模型、处理区域、数据不用于训练条款、保留/删除、成本预算和超时上限未完成审批。
- 职位要求与候选人脱敏投影 Schema、Prompt 版本、残留 PII 扫描和输出 Schema 验证未通过虚构 Fixture 回归。
- LLM 适配器能读取联系方式保险箱、未脱敏原始简历、供应商候选人 ID 或可使用页面令牌。
- 超时、限流、Schema 无效或安全拒绝会伪造分数、静默切换未审批模型或使候选人自动进入触达池。

> **境内 LLM 接入审批记录（2026-08-16，项目负责人确认）**：真实 LLM 详情评分经 **境内网关** 启用——
> - 供应商/模型：opencode.ai（**境内托管网关**）→ `deepseek-v4-flash`；`LLM_PROVIDER=deepseek`、`LLM_BASE_URL=https://opencode.ai/zen/go`、`LLM_MODEL=deepseek-v4-flash`。
> - 处理区域：**境内**（opencode.ai 境内网关，无数据出境，不触发 ADR-003 跨境评估；境外网关使用仍受 §ADR-003 默认禁止约束）。
> - 数据不用于训练 / 保留/删除：以 opencode.ai 境内网关条款为准；出网数据仅为 `residual_pii_scan=passed` 的脱敏候选人投影（无姓名/联系方式/本地或供应商 ID/原始 URL），最小化出网。
> - 成本预算：每职位 Top-K=10、单轮全局预算=20（现有成本闸）；月度预算待网关账单口径确定。
> - 超时上限：`LLM_TIMEOUT_MS=60000`（默认）。
>
> **启用条件（审批记录后仍须执行，未完成前真实 LLM 调用保持关闭）**：
> 1. `.env.production` 配 `MATCH_SCORING_ADAPTER=llm-openai-compatible` + 上方 `LLM_*` 键（`LLM_API_KEY` 走部署 Secret Manager，不入库/日志/任务载荷/审计）；
> 2. `MATCH_AUTOMATION_ENABLED=true`；
> 3. **受控真实调用验证**：确认 `https://opencode.ai/zen/go/chat/completions` 端点路径有效（适配器在 base URL 后拼 `/chat/completions`）；首次调用核对 `llm_score_runs` 落 succeeded、matches 分数非 fake、`LLM_*` 失败码可追溯。
