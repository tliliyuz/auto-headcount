# 实施路线图

本文档是「零推荐职位激活系统」的权威实施计划，回答：按什么顺序交付、每个里程碑的进入/退出条件是什么、当前推进到哪一步、谁在阻塞。产品范围见 [项目章程](00-project-charter.md) 与 [MVP 需求](01-mvp-requirements.md)，验收条件见 [验收标准](07-acceptance-criteria.md)。

以下周期按一名主要开发者估算，外部接口、短信模板、部署审批延迟不计入开发时间。

## 1. 里程碑状态定义

| 状态 | 定义 |
|---|---|
| 未开始 | 进入条件尚未满足，或尚未投入实施 |
| 进行中 | 进入条件已满足，正在完成规范、实现或验收 |
| 受阻 | 存在明确阻塞条件，且已记录解除条件 |
| 已完成 | 本阶段全部退出门禁已有可复核证据 |

禁止用主观完成比例替代门禁结果。状态变化必须能在 [变更日志](../CHANGELOG.md) 中找到对应的实际验证记录。

## 2. 里程碑总览

| 里程碑 | 状态 | 名称 | 核心结果 | 主要依赖 |
|---|---|---|---|---|
| M0 | 进行中 | 接口与样本验证 | MCP 接口清单、脱敏样本与已接受的身份/区域/数据生命周期方案 | 无 |
| M1 | 已完成 | 数据底座 | 可重复同步并查询沉睡职位与候选人的内部系统 | M0 |
| M2 | 进行中 | 摘要与匹配 | 可复算、可审核的职位—候选人匹配池 | M1 |
| M3 | 未开始 | 落地页与触达 | 从审核到候选人反馈的可运行闭环 | M2 |
| M4 | 未开始 | 漏斗与推荐 | 可演示、可度量、可验收的 MVP | M3 |

主线：`M0 → M1 → M2 → M3 → M4`。M1 已在 M0 技术门禁通过后按「最低权限开发假设」提前起建；真实数据上线仍以 M0 的书面授权门禁为准。

- 建立人工审核页面。

### 必须完成的规范

### 主要交付物

可复算、可审核的职位—候选人匹配池。

### 退出门禁（来自 [验收标准](07-acceptance-criteria.md) §2）

- [ ] 职位和候选人摘要不超过 150 个中文字符且不包含联系方式。
- [ ] 同一规则版本、同一输入可得到可复算的维度分和总分。
- [ ] 85 分及以上标记为高匹配，75～84 标记为中匹配；每个匹配至少展示匹配证据、缺失项、风险提示三类信息。
- [ ] 只有审核通过的候选人可以进入触达活动。
- [ ] 验证证据已记录到 `CHANGELOG.md`。

### 本阶段不做

- 不做向量检索、模型微调或自研推荐算法；匹配分以供应方 MCP 评分为准，不重复造评分引擎。

从审核到候选人反馈的可运行闭环。

### 退出门禁（来自 [验收标准](07-acceptance-criteria.md) §3）

- [ ] 候选人无法通过修改连续 ID 查看其他职位或候选人信息。

- [ ] 候选人可选择 A/B/C 或退订，重复提交不会产生冲突数据。
- [ ] 短信文案按产品规则限制为不超过 70 个中文字符；发送前可预览。
- [ ] 已退订或超过频控阈值的候选人不会进入发送队列。
- [ ] 验证证据已记录到 `CHANGELOG.md`。

### 本阶段不做

- 不接入机器人外呼或通话质检。
- 不做无人工审核的全自动群发。

### 退出门禁（来自 [验收标准](07-acceptance-criteria.md) §4、§5）

- [ ] 可追踪发送、送达/失败、点击、浏览、选择、确认联系和推荐事件。
- [ ] 看板可按职位、时间、活动和渠道查看数量与转化率。
- [ ] "有兴趣"会建立人工跟进任务。
- [ ] 推荐操作具备幂等性，并保存外部结果或 Portal 操作记录。
- [ ] 管理操作、数据导出和推荐操作均可审计。
- [ ] 系统具备停止活动、撤销链接和禁用外部连接的开关。
- [ ] 已完成一次数据库备份恢复和一次外部服务故障演练。
- [ ] 验证证据已记录到 `CHANGELOG.md`。

### 本阶段不做

- 不做多租户计费、复杂组织架构和完整 CRM。
- 不建设企业客户自助门户、职位发布和客户侧运营后台。

## 后续迭代

- 语义向量召回与基于反馈的排序优化。
- 多版本文案与受控实验。
- 机器人外呼及转人工。
- 多租户、计费、组织权限和客户自助门户。

## 路线图维护规则

- 状态更新必须引用 `CHANGELOG.md` 中实际验证记录；不得用主观完成比例替代门禁结果。
- 只有全部退出门禁满足后才能把里程碑标记为"已完成"。
- "受阻"必须记录阻塞条件、影响范围、责任边界和解除条件。
- 产品范围变化先更新 [MVP 需求](01-mvp-requirements.md)；架构、数据库或技术基线变化先更新 [系统架构](02-architecture.md) 与对应 ADR。
- 路线图变化同步记录到 `CHANGELOG.md`，并更新根目录 `README.md` 的"当前阶段"。
