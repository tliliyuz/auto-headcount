# 实施路线图

以下周期按一名主要开发者估算，外部接口、短信模板、部署审批延迟不计入开发时间。

## 里程碑 0：接口与样本验证（2～3 天）

- 轮换已暴露的 MCP 凭证。
- 完成 `initialize`、`tools/list` 和最小工具调用。
- 获得 10～20 个脱敏职位和候选人样本。
- 固化字段映射、数据权限和沉睡职位口径。
- 确认 OIDC 提供方、测试/生产区域、候选人数据落库授权和最终保留期限。
- 按已接受的 `ADR-003` 核验 OIDC、区域和数据生命周期的外部前置条件。

交付物：接口清单、脱敏夹具、字段字典、数据流图、权限矩阵、保留清单、风险清单和已接受 ADR。

## 里程碑 1：数据底座（3～5 天）

- 建立 Docker Compose 开发环境、PostgreSQL 迁移、OIDC 登录与服务端 RBAC。
- 实现 MCP 连接、同步批次、原始快照和规范化入库。
- 建立职位/候选人列表、分类和异常数据页。
- 实现应用层加密、追加写审计、保留任务和恢复演练入口。

交付物：可重复同步并查询沉睡职位与候选人的内部系统。

## 里程碑 2：摘要与匹配（4～6 天）

- 实现摘要服务及版本管理。
- 实现硬过滤、关键词评分、分层和解释。
- 支持外部 `match_candidates` 结果对照。
- 建立人工审核页面。

交付物：可复算、可审核的职位—候选人匹配池。

## 里程碑 3：落地页与触达（5～7 天）

- 实现脱敏职位页、随机令牌和过期/撤销。
- 实现 A/B/C、退订与联系方式确认。
- 生成短信/邮件草稿并接入一个渠道或导出清单。
- 加入人工审批、频控和幂等发送。

交付物：从审核到候选人反馈的可运行闭环。

## 里程碑 4：漏斗与推荐（3～5 天）

- 建立事件采集、聚合和看板。
- 创建人工跟进任务和结果登记。
- 接入推荐 MCP 或记录 Portal 操作。
- 完成权限、安全、备份和故障恢复检查。

交付物：可演示、可度量、可验收的 MVP。

## 后续迭代

- 语义向量召回与基于反馈的排序优化。
- 多版本文案与受控实验。
- 机器人外呼及转人工。
- 多租户、计费、组织权限和客户自助门户。
