# MVP 验收标准

## 1. 数据获取

- 能从测试 MCP 拉取沉睡职位，支持至少一次分页或游标同步。
- 发布恰好满 7 天和恰好满 30 天、状态有效、有效推荐数为 0 的职位会被纳入；不足 7 天、超过 30 天、已失效或已有有效推荐的职位不会被纳入。
- 重复执行同步不会产生重复职位。
- 可按类别、发布时间、沉睡时长和同步状态筛选。
- MCP 超时、鉴权失败和限流会给出可操作错误，不泄露凭证。
- Web 采集通过预审核的版本化只读契约运行；重复采集同一内容不产生重复实体，页面结构变化时返回 `PAGE_CONTRACT_CHANGED` 且不写入错误字段。
- 猎必得批量发现只接受当前列表已选择“推荐 0 人、发布时间最近 30 天”的证据；发现后的详情任务仍逐项执行 7～30 天权威复核，0～6 天项记为跳过且不得写入 `jobs`。
- 浏览器离线、登录失效、验证码、429 和权限边界分别进入可操作状态，不静默切换用户、设备或平台账号。
- Web 来源只有在明确取得职位状态、发布时间/沉睡天数和有效推荐数证据后才能独立进入沉睡池；“页面可见”不能替代 7～30 天零推荐规则。
- 每个生产浏览器提取契约具有版本化请求/回执 Schema、完全虚构 Fixture、Provider/Consumer 契约测试和失败关闭语义；字段、来源或敏感数据边界发生不兼容变化时升级版本，不静默修改既有版本。
- 受控真实 Web 联调按 Runbook 记录授权范围、两端版本、最小结果摘要和敏感数据检查；验证记录不包含真实页面正文、完整外部 ID、完整浏览器会话标识或可复用凭证。
- 运营在猎必得完成目标筛选后，只需选择本批数量并触发一次采集；`browser_job_batch_discover` 会验证筛选证据，按差分口径读取该来源已入库职位集合，跳过已入库且标题未变的职位，用 `nextPage`/`nextOffset` 数字断点向后翻页直到发现 `batchSize` 个「新增 + 标题变化」职位或结果末尾，保存断点并为每个发现项创建详情任务。结果末尾即停止，不允许无限翻页；已入库且标题未变的不创建条目、不耗详情提取。
- 列表合同仅返回职位 ID、标题、页码、页内序号、筛选证据、停止原因和内容哈希；不得返回页面正文、任意 URL、选择器、浏览器 session 或凭证。重复发现同一批次/职位不会创建重复条目或详情任务。
- 单设备 MVP 的管理端批量请求不提交 `userId/deviceId`；服务端只从 `BROWSER_RELAY_USER_ID`、`BROWSER_RELAY_DEVICE_ID` 读取固定路由。任一配置缺失时返回配置错误且不创建批次，客户端伪造同名字段不得覆盖服务端绑定。

## 2. 摘要与匹配

- 职位和候选人展示摘要不超过 150 个字符且不包含联系方式或直接身份标识；硬过滤不得只读取摘要。
- 职位要求投影和候选人脱敏匹配投影通过对应 v1 JSON Schema，并可追溯到生成器/脱敏版本、源快照、输入哈希和生成时间；源数据变更会新建投影而不覆盖旧投影。
- 第一阶段硬过滤在同一投影哈希和规则版本下得到相同通过/剔除结果及原因；未通过者不会创建 LLM 调用。
- 候选人脱敏投影包含 `residual_pii_scan=passed`；残留姓名、联系方式、详细地址、供应商候选人 ID 或原始 Portal 令牌时，LLM 调用被拒绝。
- LLM 输出通过 `llm-detail-score/v1` Schema，七个维度都显式标记可评估性；证据不足的维度为 `score:null`，不猜测分数。
- 每次 LLM 运行保存适配器/模型标识及可得的修订、Prompt/Schema 版本、请求/输出哈希、结构化输出、时间和机器错误码；模型或 Prompt 变更不覆盖旧运行。
- 对同一份已保存 LLM 结构化输出和同一汇总规则，重算得到相同维度分、总分和分档；不要求重新调用 LLM 逐分一致。供应方分数变化不改变本地汇总结果。
- LLM 超时/限流只有限重试；Schema 无效、PII 扫描失败、输入超限和安全拒绝失败关闭。失败时不伪造分数、不回退供应商分数且不自动触达。
- 新增或变更后的可消费投影会由系统自动进入匹配编排；运营端和公开管理 API 均不能通过勾选职位创建正常匹配任务。
- 同一职位投影、候选人投影、硬过滤规则、适配器/模型/修订、Prompt、Schema 与汇总规则版本组合至多产生一次成功 LLM 运行；周期 tick 可重复扫描，但不得重复调用。任一版本变化会新建不可变运行和匹配版本，不覆盖旧结果。
- 自动编排按稳定预排序执行单职位 Top-K 与单轮全局预算；预算外组合保留待消费状态，后续 tick 可继续处理。没有可消费组合时任务以成功空结果结束，不制造 Fixture 或评分。
- 本地开发与 CI 的 Fake LLM 通过与真实适配器相同的输出 Schema，固定输入得到固定结构化输出；生产未配置批准适配器时失败关闭。
- 匹配状态可投影为 `filter_rejected`、`scoring_pending`、`scoring_running`、`scoring_failed`、`pending_review`、`approved`、`rejected`；列表、详情和异常 API 不返回联系方式、完整简历、LLM 原始请求/响应或供应商错误正文。
- 异常 API 仅暴露白名单机器错误码与可重试性；重试只能针对失败运行，不能接受职位 ID 列表或扩大候选池。
- 85 分及以上标记为高匹配，75～84 标记为中匹配。
- 每个匹配至少展示三类信息：匹配证据、缺失项、风险提示。
- 只有审核通过的候选人可以进入触达活动。

## 3. 落地页与触达

- 候选人无法通过修改连续 ID 查看其他职位或候选人信息。
- 过期、撤销和不存在的令牌均不能访问职位详情。
- 落地页及其接口响应不包含公司名称、简称、内部职位编号或可直接识别公司的标识。
- 薪资只展示上下限范围；异常或缺少边界时不推断精确薪资，并显示安全降级文案。
- 工作地点只展示城市，不包含行政区、街道、楼宇和详细地址。
- 候选人可选择 A/B/C 或退订，重复提交不会产生冲突数据。
- 短信文案按产品规则限制为不超过 70 个中文字符；发送前可预览。
- 已退订或超过频控阈值的候选人不会进入发送队列。

### 落地页与意向切片（2026-08-14，[ADR-006](decisions/ADR-006-landing-intent-notifier.md) 已接受）

- 建链令牌为高熵随机、数据库只存哈希；明文令牌只在创建响应返回给运营，任何日志、审计或公开接口不出现明文令牌。
- 公开侧（页面/DTO）只含白名单字段：职位标题、类别、城市、薪资范围、意向操作；不包含公司名称/简称、内部职位编号、客户联系人、招聘负责人、详细地址、原始 JD，**且不输出可能泄漏公司/品牌名的 JD 摘要**（脱敏白名单见 [`03-data-model.md`](03-data-model.md) §10）。
- 意向 A/B/C/退订提交后，联系方式应用层加密入库；明文联系方式不落日志、审计或审计元数据。
- 意向重复提交幂等：同一链接重复提交返回既有记录，不产生冲突数据。
- 意向落库成功后异步投递通知（notifier 适配器，首实现飞书群机器人 webhook）：payload 仅联系方式+意向+职位+时间，按 `(candidate_id, job_id, intent_response_id)` 幂等，成功/失败写审计，失败可重试且不影响意向落库。
- 联系方式明文出库到第三方须在 ADR-006 授权范围内：仅候选人主动提交触发、仅发运营内部群、境内必要性评估、webhook 与签名 secret 走部署密钥。

## 4. 漏斗与推荐

- 可以追踪发送、送达/失败、点击、浏览、选择、确认联系和推荐事件。
- 看板可按职位、时间、活动和渠道查看数量与转化率。
- “有兴趣”会建立人工跟进任务。
- 推荐操作具备幂等性，并保存外部结果或 Portal 操作记录。

## 5. 安全与运维

- 仓库历史和构建产物不包含真实密钥或真实简历。
- 前端代码及浏览器网络请求中不存在 MCP Secret。
- 浏览器 Cookie、Authorization、口令和验证码不会离开员工浏览器，也不会进入 PostgreSQL、任务载荷、Relay/Agent 结果、普通日志或审计元数据。
- 完整简历和联系方式不通过通用 Agent/MCP 工具结果传输；受控直传 ticket 会过期、只能消费一次、绑定任务与契约并限制载荷大小。
- 匹配模块无法读取联系方式保险箱；进入 Git/CI 的候选人 Fixture 已完全虚构化，而非真实简历打码。
- 数据源具备单并发/预算、熔断、暂停和全局停止开关；连续契约失败或平台风控信号出现后停止采集。
- 浏览器预检统一返回 `READY`、`PAGE_NOT_REGISTERED`、`BROWSER_SESSION_MISSING`、`AUTH_REQUIRED`、`WRONG_ORIGIN` 或 `WRONG_ENTITY`；非 `READY` 均禁止写业务库并给出确定恢复动作。由于当前没有独立设备在线信号，不得把 `PAGE_NOT_REGISTERED` 伪装为“设备离线”；刷新或重载插件不得用于绕过权限和平台风控。
- `browser_job_collect` 任务载荷通过关闭字段 Schema，禁止 browser session、URL、选择器、脚本、页面正文和凭证；任务必须依序通过 `READY` 预检、固定合同回执、外部 ID 一致性和本地沉睡规则才可在同一数据库事务中写加密 `raw_records` 与幂等 `jobs`。7/30 天边界可写，6/31 天、非 active、发布时间/推荐数缺失或推荐数非零只记跳过且不写职位；重复任务不产生重复职位。
- 详情采集不要求运营逐个打开职位。固定详情合同在授权域名内按发现的职位 ID 做确定性导航、等待详情加载并校验实体；页面 ID 不一致、异常跳转、验证码、登录失效或合同漂移均失败关闭。
- 管理操作、数据导出和推荐操作均可审计。
- 系统具备停止活动、撤销链接和禁用外部连接的开关。
- 已完成一次数据库备份恢复和一次外部服务故障演练。

## 6. 数据底座验收

- 一条标准根目录命令可通过 Docker Compose 启动 Web、PostgreSQL 和迁移服务；健康检查通过后才能接受请求。
- 开发、测试和生产使用 PostgreSQL 17 与同一套版本化迁移；重复执行迁移不会破坏现有结构或数据。
- 测试和生产构建无法启用 Fixture 登录；未知账号、已禁用用户和无权限角色在服务端返回拒绝结果。
- 用户禁用或角色撤销后，已有管理端会话不可继续执行受保护操作。

#### 登录与账号验收（登录方案见 `01-mvp-requirements.md` §2.1）

- 正确口令登录成功并建立可撤销会话；错误口令返回统一失败文案，不泄露口令或口令哈希。
- 连续登录失败达到阈值后临时锁定并限流；锁定期满后恢复。
- 生产管理员未绑定或校验 TOTP 前不能完成登录或执行高风险操作。
- 首次登录（初始化凭证或密码被重置后）强制改密，改密前不能使用业务功能；旧口令立即失效。
- 会话空闲超时与最长有效期到期后必须重新登录；管理端写操作缺少 CSRF 防护时被拒绝。
- 登录、登出、锁定、重置与角色变更均产生审计记录，且审计不含口令与口令哈希。
- `operations`、`recruiter` 和 `admin` 的允许/禁止操作至少各有一组服务端授权测试；仅隐藏前端按钮不视为通过。
- 原始 MCP/Web 必要载荷在数据库中不是可读 JSON/明文，解密操作受权限控制并产生审计事件。
- 规范化职位可追溯到数据源、原始记录和映射版本；重复同步不覆盖原始快照。
- 审计日志不包含 Secret、Cookie、令牌、手机号、邮箱或简历正文，普通应用角色不能更新已有审计记录。
- 保留任务可按配置清理原始、规范化、审计和过期会话数据，并记录清理结果；删除流程覆盖可恢复备份的生命周期。
- 测试与生产使用不同数据库、密钥和 MCP 凭证；生产数据不得复制到开发环境。

其中自有登录、角色、区域、加密和保留相关场景已成为实现门禁；未实际运行验证前不得宣称 `verified`。

> 范围注记（2026-08-12 决策）：生产实例实际部署与生产侧验收（生产使用同一套版本化迁移、测试与生产使用不同数据库/密钥/凭证、生产数据不复制到开发环境）随开发推进顺延执行，不构成 M1 退出阻塞；部署时按本节验收。备份/恢复演练属 M5 退出门禁。
