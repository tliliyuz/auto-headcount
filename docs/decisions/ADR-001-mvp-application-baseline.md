# ADR-001：MVP 应用与开发基线

- 状态：accepted
- 日期：2026-08-11
- 决策人：项目负责人（确认“可以，开始”）

> 后续裁决：数据库与本地运行方式已由 `ADR-002` 确认为 PostgreSQL 与 Docker Compose；本 ADR 中“数据库后续另立 ADR”的等待状态在该范围内已结束。身份、区域和数据存储细节由 `ADR-003` 确定。

## 背景

项目由一名主要负责人推进，首期目标是尽快验证沉睡职位发现、匹配审核、脱敏落地页和转化追踪。外部 MCP Schema、候选人落库授权、生产区域和最终云平台尚未确认，因此不应在第一切片引入多服务、专用队列或生产数据库承诺。

## 决策

- 使用 TypeScript 和 React 构建内部运营后台。
- 当前 Web 工程使用 Vinext 的 Next.js 兼容路由与 Cloudflare Worker 兼容构建，保持页面和业务组件可迁移。
- 首个切片使用脱敏 Mock 数据验证职位规则与页面交互，不接触真实 MCP、简历或联系方式。
- 业务规则放入无框架依赖的纯函数模块，页面只消费规则结果。
- MCP、LLM、短信和邮件后续通过适配器接入，不进入页面组件。
- 数据库和任务队列在 MCP Schema、数据授权与目标部署区域确认后另立 ADR；当前不得把浏览器存储当成业务事实数据库。
- 当前 Sites 部署仅用于脱敏演示和验收，不构成生产平台承诺。

## 备选方案

### Next.js + PostgreSQL + Drizzle 一次性搭建完整后端

与既有建议一致，但在外部 Schema、数据授权和部署位置未确认时会过早固化数据库与运维方式，因此延后。

### Vue + FastAPI + PostgreSQL

技术成熟且适合前后端分离，但首期需要维护两套工程、依赖和部署入口，不符合一人快速验证目标。

## 后果

- 可以快速交付可运行、可测试的内部后台切片。
- 核心规则和组件保持清晰边界，后续可以接入真实 API。
- 当前页面数据不持久化，刷新后恢复为演示数据。
- 接入真实候选人数据前，必须补充数据库、身份权限、数据保留和生产部署 ADR。

## 重新评估触发条件

- MCP Schema 和数据持久化授权确认。
- 需要多人协作、独立 Worker 或超过数据库任务表承载范围。
- 确定中国大陆生产部署、域名和合规边界。
- 开始接入真实联系方式、简历或批量消息渠道。
